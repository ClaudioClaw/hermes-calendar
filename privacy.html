Privacy Policy

Hermes Calendar — last updated 24 November 2026

Hermes Calendar ("the app") is a private, single-user application operated by one individual for their own use. This policy describes how it handles Google user data.

What data the app accesses

The app acts as one dedicated Google account and only reaches calendars that the operator has shared with that account and listed in the app's configuration. It requests two OAuth scopes, held in two separate grants:

  • https://www.googleapis.com/auth/calendar.events.readonly (read). With it, the app reads calendar events — titles, times, locations, descriptions, and attendance status — from the configured calendars.
  • https://www.googleapis.com/auth/calendar.events (write, optional). With it, the app creates, changes, and deletes events, but only on calendars the operator has listed as writable in the app's configuration and shared with the app's account with edit rights for events. All other calendars are shared read-only, so Google refuses any change to them. The app writes event titles, times, locations, descriptions, colours and busy/free status, plus a private key it stores on the event so that it can update that event later instead of adding a copy.

The app requests no other Google data. It never sends invitations or notifications, and does not create recurring events or events with guests.

How the data is used

Calendar data is used solely to answer the operator's own questions about their schedule and, on writable calendars, to place, move, or remove events the operator has asked for. The app makes a change only after the operator has agreed to it in their conversation with the assistant. The data is not used for advertising, profiling, analytics, or training any model, and it is not used to build any user profile.

How the data is stored

The app runs on the operator's own computer. Calendar event data is held in memory only for the duration of a request and is not written to any database or long-term store by the app. Events the app writes are stored in the operator's own Google calendar, like any other event. The OAuth refresh tokens issued by Google are stored locally on that machine, with file permissions restricted to the operator, so the app can keep working without repeated sign-in.

How the data is shared

Calendar data is not sold, rented, or shared with any third party. It is shown only to the operator, who is also the account holder whose calendars are being read and written. When the operator asks a question or a change, the relevant event details are sent to the language-model provider that powers the operator's assistant, purely to phrase the answer or prepare the change; no other recipient receives the data.

Data retention and deletion

Because the app retains no calendar data of its own, there is nothing to delete beyond the stored OAuth tokens. The operator can revoke the app's access at any time from their Google Account's linked-apps settings, which immediately ends the app's ability to read or write any calendar, and can delete the locally stored tokens. Write access alone can be withdrawn by changing a calendar's share to read-only. Events the app has written stay in the operator's calendar until the operator deletes them.

Limited Use

Hermes Calendar's use of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

Children

The app has exactly one user, its adult operator. It is not directed at children.
